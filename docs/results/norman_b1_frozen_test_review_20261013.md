## What the generalization gap does and does not show

Visible validation Pearson delta is 0.780139, compared with 0.722897 held out: a descriptive drop of
0.057242. Different perturbations and category composition mean this is not a paired estimate or proof
that overfitting caused the drop. The ensemble's top-20 MSE is also worse than the additive rule's
(0.114444 versus 0.109988), so correlation alone does not capture every error.

No exploration allocation, feature or penalty was changed in response to these test numbers. The safe
next analysis uses development folds to diagnose redundancy, calibration and adaptive validation reuse;
a subsequent revised model requires fresh evaluation. The concrete feedback leak is fixed by the accompanying code change:
new continuation metadata omits the earlier model's sealed score, and legacy metadata is filtered before
the actual planner request is constructed. This preserves visible selection and historical results.

## Why the CellForge column is contextual

The values above agree with [CellForge v2 Table 1](https://arxiv.org/html/2508.02276v2#S5.T1) and the lab's
archived transcription. The paper reports SD across three generated models, whereas Appendix J describes
five independent runs without establishing the selection connecting them. Pearson delta is not reported.
The paper's Appendix E.4 permits top-20 ranking by absolute log fold change or raw difference.

The [public dataset documentation](https://github.com/gersteinlab/CellForge/blob/6585ff93e452a8a0f2ad6ed8144ab6d998a3b400/docs/DATASETS.md)
instead describes a significance-based DE definition. Its
[split routine](https://github.com/gersteinlab/CellForge/blob/6585ff93e452a8a0f2ad6ed8144ab6d998a3b400/cellforge/autorun/runner.py#L58)
holds out perturbation labels and divides remaining cells into train/validation; it does not enforce
Gene-Mila's gene-grouped split. A fixed Table-1 evaluator was not located in the inspected public release,
and its [model documentation](https://github.com/gersteinlab/CellForge/blob/6585ff93e452a8a0f2ad6ed8144ab6d998a3b400/docs/MODELS.md)
says trained weights are not distributed. None of this supports a numerical superiority claim across
the two columns. A valid comparison requires both methods' predictions on identical locked data through
the same evaluator.

## Continuation boundary and next action

Current worker restrictions are procedural, not OS-level separation. The controller owns a local oracle,
and the code previously exposed the prior winner's sealed aggregate to the continuation planner via
`warm_start.json.best_sealed` → `prior_campaign.its_best.sealed`. This proves exposure, not causation for
any particular result. The minimal prompt fix closes this explicit path but cannot undo past exposure
or prevent same-user filesystem access.

No new untouched real-data cohort is available locally, and no frozen inference adapter for a new cohort
has been verified. See the [prospective test plan](../FROZEN_TEST_PLAN.md) for the required separate
evaluator, immutable model/prediction receipts, access checks, metric batch and development-only response
to a performance drop. No test-label access, protected-code edit, API spending or new bundle is authorized
implicitly by this report.
